# M14: what Marker and MinerU do, and what is worth taking

_Read on 7 September 2026 from the public repositories (`datalab-to/marker` and `opendatalab/MinerU`, both at `master`), ideas only: no code was copied and TrueDoc takes no dependency on either. Everything below is what the source files say, not what their papers claim._

## The short version

- **Marker on the same footing as us scores the same as us.** Marker's README reports three modes on olmOCR-bench: balanced 76.0 (its vision model does layout, OCR and equations), fast 66.6 (a light layout detector, the text layer, the vision model only where the text layer fails), and fast-no-OCR 43.6 (text layer only). TrueDoc run 48 is 66.7 with no Marker model at all. Their pure text-layer mode is 23 points below us, mainly because Marker never reads formulas from the text layer ("pdftext cannot represent math"); our formula section is 86.8.
- **Marker's model weights are closed to us at any size.** The code is Apache 2.0, but the Surya weights (layout, OCR, equations, the OCR-error classifier) carry a modified OpenRAIL-M that forbids commercial use above 5 million dollars of revenue or funding *and* forbids use by anyone offering a competing product. A document-conversion service competes. Only their ideas are usable.
- **MinerU's licence changed and is now usable.** Since 3.1 (April 2026) it is the "MinerU Open Source License": Apache 2.0 plus attribution in the product or its documentation, with a commercial licence needed only above 100 million monthly users or 20 million dollars of monthly revenue. Our roadmap's AGPL note applied to 2.5 and is out of date. MinerU's pipeline models are the PaddleOCR family (Apache 2.0): PP-DocLayoutV2 for layout with a reading-order head, PP-OCRv6 for OCR, PP-FormulaNet-plus-M and UniMERNet for formulas, SLANet-plus and a UNet model for tables. All run on CPU.
- **Reading order is a model in both tools.** MinerU sorts blocks by the `index` its layout model emits. Marker's layout model has an order head for scanned pages, but on pages with a text layer it orders blocks by the PDF's own character stream, which it calls "the most reliable reading-order signal for multi-column layouts". That is the one mechanical idea here that we do not use.
- **Tables from the text layer: Marker scores candidate grids; we pick one.** Marker builds two column grids (one from the modal number of spans per row, one from whitespace projection at three coverage levels), scores each on column purity, compound cells, fill, header agreement and one-span-per-cell, keeps the best, and falls back to OCR of the table image when the score is under 0.75. Its wrapped-line attachment, header band and leader stripping are close to ours.
- **Both tools re-read the text layer where it is bad, at block or span level; we reject whole pages.** Marker OCRs individual empty or garbled blocks on otherwise good pages; MinerU re-OCRs a span when private-use characters appear and drops low-contrast crops.

## Marker, file by file

**Licences** (`README.md`, `MODEL_LICENSE`): code Apache 2.0. Weights: "AI Pubs Open RAIL-M (modified), version 0.1": commercial use only under 5 million dollars of revenue and of funding; "entities offering competing products/services are prohibited"; outputs unrestricted; attribution required.

**Published numbers** (`README.md`, olmOCR-bench, 1,403 PDFs): balanced 76.0 (digital-only 83.5, 2.9 pages a second on a GPU); fast 66.6 (71.6; 7.4 pages a second); fast without OCR 43.6 (55.8; 23.7 pages a second on CPU). Their own measurements of others: MinerU 72.7, docling 50.3.

**Text layer and the OCR decision** (`providers/pdf.py`, `builders/line.py`, `builders/ocr.py`):
- pdftext extracts spans, lines and fonts, with the character stream position kept per span.
- A page keeps its text layer only past four gates: `check_page` (there are text objects; text is not invisible; fonts are embedded and not "glyphless"; images cover under 0.65 of the page), `detect_bad_ocr` (spaces over letters-plus-spaces no more than 0.7; newlines no more than 0.6 of characters; alphanumeric density at least 0.3; replacement characters under max(6, 3 percent)), an OCR-error classifier run over the page text (a small model: pages it marks bad go to full-page OCR), a layout-coverage test (at least a quarter of the layout blocks must hold a text-layer line, unless the page is one large text block), and an overlap test (if more than half the lines overlap two or more other lines, the layer is a duplicate or corrupt: "A few overlapping lines from inline math or figure labels are expected on clean digital PDFs").
- On a good page, single blocks still go to OCR when they are empty but large (over 1 percent of the page, not blank ink, not mostly inside a sibling) or garbled (at least 50 characters, page error score at least 0.05); figures, tables, forms, equations, headers and footers never do. In balanced mode any flagged block promotes the whole page to OCR; in fast mode only when more than half the blocks are flagged.
- Reading order on text-layer pages: layout blocks are sorted by the smallest character-stream position of the text they contain; blocks with no text inherit the position of the block before them. Scanned pages use the layout model's order head.

**Tables from the text layer** (`processors/table.py`, `processors/table_recon.py`): scanned pages trust the OCR model's HTML; digital pages call `reconstruct_table_html(lines)`, which returns HTML and a score; below 0.75 (balanced) or 0.5 (fast) the table crop is OCR'd instead. The reconstruction: rows are lines with at least two spans; leaders (`^[.·•…_\-\s]+$`) are dropped first; a garble gate rejects text with over 2 percent private-use or replacement characters; the header band is every row above the first row whose spans are mostly numbers; column grid A takes the modal span count k, needs at least three "anchor" rows with exactly k spans, places cuts at midpoints between the per-column median left edges (or centres); grid B projects row coverage onto x at 1, 3 and 10 percent of rows and cuts between runs, merging runs closer than 2.5 points; each candidate is scored (purity of cell types per column, share of cells without a compound "two numbers in one text cell", fill, header cell count against k, and double weight on cells holding exactly one span) and the best wins; short lines inside the table attach to the row above in "texty" columns; columns whose cells are one or two symbols merge into the column to their right.

**Paragraphs across columns and pages** (`processors/text.py`): two blocks are one paragraph when the first block's last line runs full width or ends in a hyphen (`[\p{Ll}|\d][-—¬]\s?$`), the next block does not start indented, and the blocks sit in columns (a gap of at least 2 percent of the page width) or the next starts in the first quarter of its page.

**Headings** (`processors/sectionheader.py`): line heights of all headings are clustered with k-means into four levels; clusters whose mean is within 25 percent of the one above merge; a heading no cluster claims gets level 2.

**Running heads and feet** (`processors/page_header.py`, `processors/ignoretext.py`): page headers are kept and moved to the top of the page; text repeated on at least 20 percent of pages (minimum three) or three pages running, matched at 90 percent similarity with leading and trailing digits stripped, is dropped. On a single page nothing is dropped, which is why Marker's headers score (86.6) trails ours (96.3).

**Footnotes** (`processors/footnote.py`): kept, moved to the end of the page, the leading digits or symbols marked as superscript.

**Equations** (`processors/equation.py`): never from the text layer; a recognition model reads the image with a 2,000-token budget per block. Inline maths is suspected from font names (cmmi, stix, math) or a Unicode maths-character share over 2 percent; when 30 percent of a page's blocks are suspect, every text block is OCR'd.

**Blank pages** (`processors/blank_page.py`): a picture block covering 80 percent of the page is removed when blur, adaptive threshold, small-component removal and dilation leave no ink. Off by default.

## MinerU, file by file

**Licence** (`LICENSE.md`): "MinerU Open Source License", Apache 2.0 with two additions: attribution ("services provided to third parties based on MinerU must include clear attribution in the product interface or public documentation") and thresholds (100 million monthly active users or 20 million dollars of monthly revenue, counted with affiliates); the licence ends by itself if either is breached.

**Backends and models** (`README.md`, 3.4 of 18 June 2026): pipeline (CPU-capable; OmniDocBench 86.47), VLM (95.30, GPU), hybrid (95.39, GPU). The pipeline's models: PP-DocLayoutV2 for layout and order, PP-OCRv6 for OCR ("about 11 percent" more accurate than v5), PP-FormulaNet-plus-M and UniMERNet for formulas, SLANet-plus and a UNet table model.

**Text or scan, per document** (`utils/pdf_classify.py`): ten sampled pages; the document goes to OCR when the average cleaned characters per page are under 50; when characters that fail Unicode mapping reach 4 percent; when Type0 fonts with Identity encoding and no ToUnicode table hold at least 30 characters and 1 percent of the text; when Latin-charset fonts decode as CJK; when null, replacement, control and private-use characters reach 3 percent of at least 300 characters; on cross-script contamination and a suspicious CJK range; when punctuation runs are dense; or when enough sampled pages are at least 80 percent image.

**Spans from the text layer** (`utils/span_pre_proc.py`): the OCR detector's line boxes define the spans even on digital pages, and pdfium's characters are poured into them (a character belongs to a span when its centre is within a third of the span height of the span's centre, with edge rules for opening and closing punctuation); a space is written where a character gap exceeds a quarter of the median character width; ligatures are expanded; a span with two or more private-use characters in a run, or 5 percent of them, is re-OCR'd; a span whose character count times height is under half its width goes to OCR; a crop with contrast under 0.17 is dropped; superscripts and subscripts are found by a centre offset of 0.15 of the body height and written as `<sup>` and `<sub>`.

**Page assembly and order** (`backend/pipeline/pipeline_magic_model.py`): layout boxes carry an `index` from PP-DocLayoutV2; blocks are sorted by it; boxes under 2 pixels are dropped; captions and footnotes of figures and tables are attached to the nearest visual parent; blocks labelled header, footer, page number, aside text and page footnote are discarded and never reach the markdown.

**Paragraphs** (`backend/pipeline/para_split.py`, `pipeline_middle_json_mkcontent.py`): a list is lines left-aligned within half a line height whose right edges vary, or that end in list punctuation on 80 percent of lines; two text blocks merge when the first's last line reaches the block's right edge within a line height, the next starts without a capital or a digit, and the widths differ by less than the narrower block; a line-end hyphen followed by a lowercase line is removed and the words joined; Latin spans join with a space, CJK spans with none. Heading levels come from the layout label (document title 1, paragraph title 2) or an optional LLM pass.

## What is worth trying here, in order

1. **Reading order from the character stream on text-layer pages** (Marker). Record each block's smallest text-layer character index and order blocks by it when the page has a text layer, falling back to geometry when the stream order contradicts the geometry badly (interleaved columns from a poor OCR layer). Test on the sixteen true ordering mistakes and the multi-column subset. Cheap; the only idea in either tool that is both mechanical and absent from TrueDoc.
2. **Score several column grids and keep the best** (Marker). We have the channels-only grid and the channels-plus-voted-cuts grid; add the modal-segment-count grid, score the three on purity, compound cells, fill, header agreement and one-segment-per-cell, and keep the best. Medium effort; aimed at the seventy table checks whose text is present but wrongly structured.
3. **Header band above the first numeric-majority row** (Marker) as a check on `_header_row_count` for OCR'd tables of numbers.
4. **Trust tests for a text layer**: the overlapping-lines test and the CID-without-ToUnicode test, added to our garbage and hidden-text fractions. Cheap.
5. **Block- or span-level re-reading** where a layer is bad in places (both). We have `ocr_region`; the trigger (private-use runs, empty large blocks, an error score) is the new part. Medium.
6. **Small task models with clean licences** (MinerU's family, Apache 2.0): PP-OCRv6 recognition in place of the English v4 model (old print, the Japanese table, glued dictionary text); PP-FormulaNet-plus-M for formulas on scans (MinerU's pipeline scores 47.4 on old-scan maths where we score 4.1); SLANet-plus for picture tables. These are the "route 2" candidates: CPU, no vision-language model, licences that allow a commercial service with attribution.

What is not worth taking: Marker's heading k-means (ours is already at 96 on the headings the benchmark checks through other sections), its footnote and header handling (ours is stricter on single pages), and anything from either tool's formula path, which is entirely model-based where ours reads the text layer.
